# Hermes

One assistant that knows your projects, works across your tools, and proves what it did.

## The problem

Chat assistants give advice and forget. Agent tools do one task in one window and lose the thread.

Neither knows your projects, neither can finish work in the tools you actually use, and neither can show you what really happened. So you end up as the glue — re-explaining context, copying output between tools, doing the last mile yourself.

## What it is

Hermes is somewhere your assistant lives, not a window you open.

It keeps the context for each project — repo, live site, deploy target, search data — and you reach the same assistant from a terminal, the web, or Slack. Work can start in one place and finish in another.

Specialists do the domain work behind it: search growth, code, research, analytics, deploys. Hermes handles the context, the permissions, the approvals, and the record.

## Who it's for

Builders running a few projects at once across repos, live sites, deploys, search data, and team channels.

## Why it's better

- **It knows the project.** Not a chat history. A kept record of facts, decisions, open work, and what happened last time.
- **It finishes the work.** Opens the PR, drafts the content, checks the live page.
- **It asks first.** Anything touching a repo or a live site needs a yes from you.
- **It shows receipts.** What it looked at, what it changed, what happened after.
- **It waits.** Work can pause for days and pick up exactly where it stopped.

## What it isn't

- A general chat window
- A coding IDE agent
- An autonomous worker with no approvals

## First version

One specialist (search growth), one project, reachable from a terminal and the web.

Ask for something. Get a proposed change with the evidence behind it. Approve it. Watch it get verified on the live site. See the result kept.

More channels and more specialists come after, without changing the core.
